## Table Features

In Table v8, `useReactTable` bundled every feature. In Table v9 you import only what you need.

- **Same idea as the registry:** mix and match `DataTable*` components and install only the pieces you use.
- **Two layers:** registry items do this for the UI. This file does it for the table engine.

<div className="not-content mb-4 flex items-center gap-2">
  <DocsLink href={`${GITHUB_REPO_URL}/blob/main/src/components/niko-table/lib/data-table-features.ts`} external>Source Code ↗</DocsLink>
</div>

A feature's API exists on the table instance only once you register it.

- **Passed for you:** `DataTableRoot` hands this object to `useTable`.
- **Registration:** decides _whether the API exists_.
- **Feature detection and `enable*` flags:** decide _when_ the behavior runs.

### features

```tsx showLineNumbers
import { features } from "@/components/niko-table/lib/data-table-features"

// DataTableRoot does this internally — you only need it for a custom table.
const table = useTable({ features, data, columns })
```

`DataTableFeatures` is the type of that object. Every `DataTable*` type alias is bound to it (`DataTableInstance<TData>` is `Table<DataTableFeatures, TData>`, and so on), so you rarely name it yourself.

### createDataTableColumnHelper

A TanStack Table v9 column helper with features already bound.

- **Why:** TanStack recommends `createColumnHelper()` for static columns (typed `getValue()` in cells).
- **Problem:** the raw v9 helper needs the features generic passed by hand (`createColumnHelper<DataTableFeatures, TData>()`).
- **Fix:** this wraps it, the same way `DataTableColumnDef<TData>` binds features.

```tsx showLineNumbers
import { createDataTableColumnHelper } from "@/components/niko-table/lib/data-table-features"

const columnHelper = createDataTableColumnHelper<Product>()

const columns = [
  columnHelper.accessor("name", { header: "Name" }),
  columnHelper.accessor("price", {
    header: "Price",
    cell: ({ getValue }) => getValue().toFixed(2), // `getValue()` is `number`
  }),
  columnHelper.display({
    id: "actions",
    cell: () => <button type="button">Edit</button>,
  }),
]
```

- **Use the helper** for typed `getValue()` in cells. Put the results in a `DataTableColumns<TData>` array (what `DataTableRoot` accepts).
- **Use a plain `DataTableColumnDef<TData>[]`** for dynamic columns and easy copy-paste. Examples still use this by default.

#### Trimming it down

The shipped file registers every feature the library can use, plus the row models they need:

- sorting, filtering, faceting, grouping, aggregation
- pagination, expanding, selection
- column visibility, ordering, pinning, sizing, resizing

You own the file after install. Delete the features and the built-in `sortFns` / `aggregationFns` your tables never use.

**Watch out:** removing a feature removes its API. Calling `table.setGrouping()` without `columnGroupingFeature` fails at runtime, not at build time.

#### Adding your own filter function

Register it under `filterFns` and reference it by name from a column:

```tsx showLineNumbers
export const features = tableFeatures({
  // ...
  filterFns: {
    extended: extendedFilter,
    numberRange: numberRangeFilter,
    dateRange: dateRangeFilter,
    startsWith: (row, columnId, value: string) =>
      String(row.getValue(columnId)).toLowerCase().startsWith(value.toLowerCase()),
  },
})

const columns: DataTableColumnDef<Item>[] = [
  { accessorKey: "name", filterFn: "startsWith" },
]
```

## Filter Functions

Fast custom filter functions for TanStack Table.

<div className="not-content mb-4 flex items-center gap-2">
  <DocsLink href={`${GITHUB_REPO_URL}/blob/main/src/components/niko-table/lib/filter-functions.ts`} external>Source Code ↗</DocsLink>
</div>

This module has optimized filter functions for TanStack Table:

- **Regex caching**: caches compiled regex patterns for 70-90% faster filtering
- **Operator support**: all filter operators (ilike, eq, neq, in, between, etc.)
- **Performance**: LRU-style cache eviction prevents memory leaks

### Performance Notes

Regex caching speeds up filtering:

- **Without caching**: 1,000 rows × 10 columns = 10,000 regex creations per search keystroke (~100-500ms)
- **With caching**: First search creates regex once, subsequent searches reuse cached regex (~5-20ms)

The cache holds at most 100 entries and evicts the oldest (LRU-like) to prevent memory leaks.

A filter function that supports every operator (ilike, eq, neq, in, not_in, between, lt, gt, lte, gte, empty, not_empty). It is the default `filterFn` for columns with advanced filtering.

```tsx showLineNumbers
    accessorKey: "name",

]
```

### processFiltersForLogic

Decides where an array of `ExtendedColumnFilter` objects goes:

- **Pure AND:** goes to TanStack's `columnFilters`.
- **Any OR or mixed logic:** goes in `globalFilter`, because TanStack combines column filters with AND only.

```tsx showLineNumbers
import { processFiltersForLogic } from "@/components/niko-table/lib/data-table"

const {
  processedFilters, // filters with normalized joinOperator values
  hasOrFilters, // any rule joined with OR
  hasSameColumnFilters, // multiple rules target one column
  shouldUseGlobalFilter, // true → route via globalFilter, not columnFilters
  joinOperator, // "and" | "mixed"
} = processFiltersForLogic(filters)
```

### createScrollHandler

Builds a scroll handler that reads container metrics on each `scroll` event and calls:

- `onScroll` with a `ScrollEvent` snapshot (`scrollTop`, `scrollHeight`, `clientHeight`, `isTop`, `isBottom`, `percentage`)
- `onScrolledTop` when `scrollTop === 0`
- `onScrolledBottom` when within `scrollThreshold` pixels of the end

Attach the returned listener with `addEventListener("scroll", handler, { passive: true })`. The browser can then keep scrolling on its compositor thread (smoother on mobile and with virtual scroll).

```tsx showLineNumbers
import { createScrollHandler } from "@/components/niko-table/lib/create-scroll-handler"

React.useEffect(() => {
  const container = containerRef.current
  if (!container) return
  if (!onScroll && !onScrolledTop && !onScrolledBottom) return

  const handleScroll = createScrollHandler({
    onScroll,
    onScrolledTop,
    onScrolledBottom,
    scrollThreshold: 50,
  })
  container.addEventListener("scroll", handleScroll, { passive: true })
  return () => container.removeEventListener("scroll", handleScroll)
}, [onScroll, onScrolledTop, onScrolledBottom])
```

#### Parameters

Single options object:

| Name               | Type                                      | Default | Description                                                                                                  |
| ------------------ | ----------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------ |
| `onScroll`         | `(event: ScrollEvent) => void` (optional) | -       | Called on every scroll event with a snapshot of container metrics                                            |
| `onScrolledTop`    | `() => void` (optional)                   | -       | Called when `scrollTop === 0`                                                                                |
| `onScrolledBottom` | `() => void` (optional)                   | -       | Called when within `scrollThreshold` of the bottom                                                           |
| `scrollThreshold`  | `number`                                  | `50`    | Pixel distance from the bottom that triggers `onScrolledBottom` (use a higher value for earlier prefetching) |

#### Returns

`(event: Event) => void`: the listener to attach. Your callbacks are passed once when you build it, so build it in a `useEffect` keyed on the same callbacks.

#### Notes

- For _virtualized_ infinite scroll, use `DataTableVirtualizedBody`'s `onNearEnd` and `prefetchThreshold` instead of `onScrolledBottom`. `onNearEnd` follows the virtualizer index, so it also catches:
  - fast scrolls and scrollbar drags
  - `scrollToIndex()` jumps
  - first renders where the data does not fill the viewport
- The handler reads `event.currentTarget`. Attach it directly to the scroll container, not a parent.

### isInteractiveClickTarget

Returns `true` when the click hit (or is inside) an interactive element, so `onRowClick` should not run. The per-row bodies (`DataTableBody`, `DataTableVirtualizedBody`) use it. They already know the row from `event.currentTarget.dataset.rowId`.

```tsx showLineNumbers
import { isInteractiveClickTarget } from "@/components/niko-table/lib/row-click"

const handleRowClick = (event: React.MouseEvent<HTMLElement>) => {
  if (isInteractiveClickTarget(event.target as HTMLElement)) return
  const rowId = event.currentTarget.dataset.rowId
  if (!rowId) return
  const row = table.getRow(rowId)
  if (!row) return
  onRowClick(row.original, event)
}
```

### resolveRowFromClick

For delegated `<tbody>` handlers (the DnD bodies use it). Returns the matched row, or `null` if the click should be ignored. That happens when the click hit an interactive child, or when no row could be found from the closest `tr[data-row-id]`.

```tsx showLineNumbers
import { resolveRowFromClick } from "@/components/niko-table/lib/row-click"

const handleRowClick = (event: React.MouseEvent<HTMLElement>) => {
  const row = resolveRowFromClick(event.target as HTMLElement, table)
  if (!row) return
  onRowClick(row.original, event)
}
```

#### Notes

- The interactive-element list lives in `isInteractiveClickTarget`. Add new ignored elements there.
- Rows need `data-row-id={row.id}` for delegated lookup. All built-in bodies set it. Custom bodies should too.

## Column Sizing Layout

Helpers that make a resizable table fill its container and keep header labels readable. Flex fill and header-fit turn on automatically with column resizing. Auto-fit and persistence are opt-in.

### resolveFlexColumnIds

Picks which column(s) render widthless so they take the leftover row width (flex fill).

- **On by default** for resizable tables. The first non-pinned, resizable data column takes the extra space, so the table fills its container with no gap on the right.
- **Pure layout:** it never writes `columnSizing`, so nothing gets saved.

Overrides via column or table `meta`:

- `meta.flex === true`: that column flexes.
- `meta.flex === false`: that column is skipped.
- `TableMeta.disableFlexFill === true`: fill is off for the whole table.
- A column the user resized keeps their width. The fill moves to the next eligible column.

### resolveColumnWidth

The width to render for one column. It keeps the flex and header-fit rules in one place, so the header, body cells, and min-width lock agree.

- **Resizing off:** the declared `size`.
- **Flex column:** `undefined`.
- **User-resized column:** exactly `getSize()`.
- **Otherwise:** at least the header's natural width, so the label is never cut off on load.
- **Pure layout:** `headerMinWidths` is measured and never written to `columnSizing`.

### useHeaderMinWidths

Measures each header's natural width off-DOM (a reusable canvas, so no reflow). Columns the user has not resized get at least that width (header-fit), so labels are not cut off on load.

- **Returns:** a `columnId → minWidth` map.
- **Resized columns:** left alone.
- **Pure measurement:** nothing is written to `columnSizing`.
- **Recomputes:** only when visible columns, their labels, or the header font change.

### useColumnAutoFit

An even-split alternative to single-column flex fill.

- **What it does:** on load (and when the container grows or columns toggle), it gives each resizable column an equal share of the leftover space. It seeds `columnSizing`.
- **When it stops:** for good once the user resizes a column or a saved `columnSizing` is restored.
- **How to use it:** most people add the opt-in [`<DataTableColumnAutoFit />`](/niko-table/overview/components/#datatablecolumnautofit) component instead of calling this hook.

### useColumnSizingPersistence

Opt-in `localStorage` saving for resized column widths. Column sizing is controlled state on `<DataTableRoot>`, so this hook owns it. Pass the returned `columnSizing` and `onColumnSizingChange` to the table, and widths survive reloads.

- **Writes at once:** resizing runs in `onEnd` mode, so it saves once per drag.
- **Syncs across tabs:** via the native `storage` event. An unchanged read keeps the same state object, so idle tabs do not re-render.
- **Cleans bad data:** corrupt or hand-edited storage never reaches `column.getSize()`.
