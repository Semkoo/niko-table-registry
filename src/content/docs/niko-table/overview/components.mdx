
#### Props

| Name                  | Type                                   | Default      | Description                                           |
| --------------------- | -------------------------------------- | ------------ | ----------------------------------------------------- |
| `autoOptions`         | `boolean`                              | `true`       | Auto-generate options for select/multiSelect columns. |
| `showCounts`          | `boolean`                              | `true`       | Show counts beside each option.                       |
| `dynamicCounts`       | `boolean`                              | `true`       | Recompute counts based on filtered rows.              |
| `limitToFilteredRows` | `boolean`                              | `true`       | Generate options from filtered rows only.             |
| `includeColumns`      | `string[]`                             | -            | Only generate options for these column ids.           |
| `excludeColumns`      | `string[]`                             | -            | Exclude these column ids from generation.             |
| `limitPerColumn`      | `number`                               | -            | Limit number of generated options per column.         |
| `mergeStrategy`       | `"preserve" \| "augment" \| "replace"` | `"preserve"` | How to handle existing static options.                |
| `className`           | `string`                               | -            | Additional CSS classes.                               |

#### Merge Strategy

| Value      | Description                                        |
| ---------- | -------------------------------------------------- |
| `preserve` | Keep user-defined options untouched (default).     |
| `augment`  | Add counts to matching values from static options. |
| `replace`  | Override static options with generated options.    |

### DataTableFacetedFilter

A faceted filter for single or multiple selection. Options are generated from your data.

<div className="not-content mb-4 flex items-center gap-2">
  <DocsLink href={`${GITHUB_REPO_URL}/blob/main/src/components/niko-table/components/data-table-faceted-filter.tsx`} external>Source Code ↗</DocsLink>
  <DocsLink href={`${GITHUB_REPO_URL}/blob/main/src/components/niko-table/filters/table-faceted-filter.tsx`} external>Filter Implementation ↗</DocsLink>

```tsx showLineNumbers
import { DataTableFacetedFilter } from "@/components/niko-table/components/data-table-faceted-filter"

// With static options
<DataTableFacetedFilter
  accessorKey="category"
  title="Category"
  options={[
    { label: "Electronics", value: "electronics" },
    { label: "Clothing", value: "clothing" },
  ]}
  multiple
/>

// Auto-generate options from data
<DataTableFacetedFilter
  accessorKey="brand"
  limitToFilteredRows={true}
/>
```

#### Props

| Name                  | Type                   | Default     | Description                                              |
| --------------------- | ---------------------- | ----------- | -------------------------------------------------------- |
| `accessorKey`         | `keyof TData & string` | -           | Column accessor key (required).                          |
| `title`               | `string`               | -           | Custom title (uses `column.meta.label` if not provided). |
| `options`             | `Option[]`             | -           | Static options array.                                    |
| `multiple`            | `boolean`              | -           | Allow multiple selection.                                |
| `showCounts`          | `boolean`              | `true`      | Show counts beside each option.                          |
| `dynamicCounts`       | `boolean`              | `true`      | Recompute counts based on filtered rows.                 |
| `limitToFilteredRows` | `boolean`              | `!multiple` | Show only options from filtered rows.                    |

#### limitToFilteredRows

Sets whether the filter lists options from all rows or only the filtered rows.

- **`true`:** options come from rows that match the other active filters.
  - Good for a "Brand" filter where you only want relevant options.
  - Default for single-select (`multiple={false}`).
- **`false`:** options come from all rows, whatever the other filters say.
  - Good for a "Category" filter where you want every option.
  - Default for multi-select (`multiple={true}`).

### DataTableViewDndMenu

A drag-to-reorder version of `DataTableViewMenu`.

- **Handles:** each row gets a `GripVertical` handle. The list sorts vertically via `@dnd-kit`.
- **One state:** the table's `columnOrder` state drives the menu order. Dropping a row updates both.

```tsx showLineNumbers
    accessorKey: "category",

        <DataTableColumnTitle />

          multiple
          limitToFilteredRows={false}
        />
      </DataTableColumnHeader>
    ),
    meta: { label: "Category" },
    enableColumnFilter: true,
  },
  {
    accessorKey: "price",
    header: () => (
      <DataTableColumnHeader>
        <DataTableColumnTitle />
        <DataTableColumnSortMenu variant={FILTER_VARIANTS.NUMBER} />
        <DataTableColumnSliderFilterMenu />
      </DataTableColumnHeader>
    ),
    meta: { label: "Price", variant: "range" },
    enableColumnFilter: true,
  },
  {
    accessorKey: "releaseDate",
    header: () => (
      <DataTableColumnHeader>
        <DataTableColumnTitle />
        <DataTableColumnSortMenu />
        <DataTableColumnDateFilterMenu />
      </DataTableColumnHeader>
    ),
    meta: { label: "Release Date", variant: "dateRange" },
    enableColumnFilter: true,
  },
]
```

#### How Context Works

`DataTableHeader` and `DataTableVirtualizedHeader` call `flexRender(...)` to draw the JSX your `header` function returns. The core components wrap that JSX in the `<DataTableColumnHeaderRoot column={...}>` provider.

So every component inside your `header` function (`DataTableColumnHeader`, `DataTableColumnTitle`, etc.) gets the column context. This holds even if you compose by hand in your `columns` definition.

#### Advanced: Context Provider and Hook

For custom setups, you can use the column header context directly:

##### DataTableColumnHeaderRoot

The provider that gives column context to child header components. `DataTableHeader` and `DataTableVirtualizedHeader` use it inside. You only need it for a fully custom header renderer.

### DataTableColumnResize

Opt-in column resizing. Put `<DataTableColumnResize />` inside `DataTableRoot` to add drag grips (plus keyboard nudge and double-click autosize) to every header that allows resizing.

- **Works with:** regular and virtualized headers.
- **Opt out per column:** `enableResizing: false`.
- **Flex fill (on by default):** one column takes the leftover width so the table fills its container. Dragging the fill column fixes its width and moves the fill to the next eligible column.
- **Header-fit (on by default):** columns you have not resized are at least as wide as their header label, so labels are not cut off.
- **Drag preview:** a guide line shows the drag. The new width applies on release (`columnResizeMode: "onEnd"`).

See the [Column Resize Table](/examples/column-resize-table/) example.

```tsx showLineNumbers
import { DataTableColumnResize } from "@/components/niko-table/components/data-table-column-resize"

  </DataTable>
</DataTableRoot>
```

## Column Header Internal Helpers

The column header is split into small files.

- **Entry point:** `DataTableColumnHeader` (above). You render it in your column `header` callbacks.
- **Building blocks:** the pieces below. `DataTableColumnHeader` uses them inside.
- **Why they are exported:** for a fully custom header, you can use only the parts you want (for example just the sort menu, or just pin and hide). Most people never import them.
