## Prerequisites

You need:

1. **A React project** (Next.js, Vite, etc.)
2. **Shadcn UI** set up in your project ([Installation Guide](https://ui.shadcn.com/docs/installation)). Radix UI (`new-york`, `radix-*`), Base UI (`base-*`) and React Aria (`aria-*`, experimental) styles all work.
3. **TailwindCSS** configured
4. **TypeScript** (recommended)
5. **TanStack Table v9** (`@tanstack/react-table@^9`). The CLI sets this version when you install registry items. To add it by hand, run:

   <CliCommandCode action="install" command="@tanstack/react-table@^9" />

**Radix UI and Base UI use the same source.** React Aria has its own build ([see below](#radix-ui-base-ui-and-react-aria)).

- **Radix style:** `"new-york"` works.
- **Base UI style:** `"base-nova"` works. It is the current `shadcn init` default.
- **Type errors after install?**
  - Update to a recent `shadcn` CLI.
  - Re-add the block with `--overwrite`.
- **How it works:** The source typechecks against both styles. The CLI swaps Radix idioms for Base UI ones during install (`asChild` becomes `render`).

## Configure the registry

Register the `@niko-table/` namespace in your `components.json` so the shadcn CLI can find it. Add the `registries` field:

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  // ... your existing config (style, tailwind, aliases, etc.)
  "registries": {
    "@niko-table": "https://niko-table.com/r/{style}/{name}.json"
  }
}
```

> **Tip:** Don't want to edit `components.json`? Install by URL instead (see the URL commands below).
>
> - These URLs install the Radix UI and Base UI version.
> - On React Aria, put your style in the URL: `https://niko-table.com/r/aria-nova/<name>.json`. Use the `style` from your `components.json`.

### Radix UI, Base UI and React Aria

The same line works for all three. The CLI reads `style` in your `components.json` and gets the matching version.

- **Radix UI** (`new-york`, `radix-*`) and **Base UI** (`base-*`): supported.
- **React Aria** (`aria-*`): new and experimental.
  - It needs the `registries` line above. Without it, the CLI uses the shadcn directory entry for `@niko-table`, which installs the Radix version.
  - Known gaps:
    - Popovers, menus and the right-click menu are always modal: the page does not scroll while one is open.
    - Arrow keys do not move between menu items and a search box or other controls inside the same menu. Tab and the mouse do.
    - Right-click menus do not open with a long press on touch, and after one closes, focus goes to the page, not the row.
    - Search in filters and menus matches text that contains what you type. It does not do fuzzy matches, and results keep their order.
    - The first Escape in a search box clears it. The next one closes the popover.
    - In the drag-to-reorder column menu, arrow keys do not move between rows. Tab, Enter and the mouse do.
    - A picked date cannot be cleared by clicking it again, and a date range only reports once both ends are picked.
    - Help icons with a tooltip are an extra Tab stop, and tooltips open on hover only after a first click on the page.
    - shadcn's React Aria `components/ui/label.tsx` imports `React` but never uses it. That fails strict TypeScript (`noUnusedLocals`). Delete the import line. This is a shadcn issue, not Niko Table.
- Already using `https://niko-table.com/r/{name}.json`? It still works on Radix and Base UI. Switch to the line above to get React Aria.

## Installation

Install in two steps, or all at once:

1. **Install the owner once.** `@niko-table/data-table` copies `DataTableRoot`, the table chrome, `data-table-core` and `data-table-ui` into your project.
2. **Add features one by one.** Run the CLI for each feature you need (pagination, search filter, DnD, etc.).
   - Each add-on depends on `data-table-core`. The CLI installs or reuses it.
   - It does not pull in Root or overwrite `table.tsx`.

Install the owner now:

<Installation registryItem="data-table" />

**This installs the full table owner** (`data-table`, `data-table-core` and `data-table-ui`).

- **Includes `lib/data-table-features.ts`.** This is TanStack Table v9's feature list. `DataTableRoot` passes it to `useTable`.
- **Trim it after install.** Remove the features you never use. See [Table Features](/niko-table/introduction/#table-features-tanstack-table-v9).
- **Need more?** Add the optional blocks below one by one, or use **Install Everything**.
- **Own the TanStack instance?** Skip `data-table` and install the control items directly. See [Components](/getting-started/components/#core).

## Architecture Note

DataTable has two layers:

- **Components** (`data-table-*.tsx` in `/components`): wrappers that get the table from `DataTableRoot` context through `useDataTable()`. You do not pass props down. This is the recommended layer.
  - Examples: `DataTableSearchFilter`, `DataTableFilterMenu`, `DataTableSortMenu`, `DataTablePagination`.
- **Filters** (`table-*.tsx` in `/filters`): the core pieces. They take a `table` prop and read the TanStack Table instance (like `table.state` and `table.setGlobalFilter()`). You can use them on their own.
  - Examples: `TableSearchFilter`, `TableFilterMenu`, `TableSortMenu`.

**Why two layers?**

- **`DataTable*` components:** import from their direct paths (e.g. `@/components/niko-table/components/data-table-pagination`). They work with no setup.
- **`Table*` filters:** import from filters (e.g. `@/components/niko-table/filters/table-pagination`). Use them to build your own components or manage the table instance yourself.
- **Your control:** all filter components use TanStack Table hooks directly.

Learn more in the [Introduction](/getting-started/introduction/#state-management-with-react-context).

## Custom Table Component

`@niko-table/data-table` pulls in `@niko-table/data-table-ui`. That installs a custom `components/ui/table.tsx`, which adds these to the default Shadcn table:

- **`TableComponent` export.** A plain `<table>` without the scroll wrapper. DataTable uses it internally.
- **`data-slot` attributes** on all elements.
- **A focusable scroll container** (`tabIndex={0}`). Keyboard users can focus it and scroll with the arrow keys (WCAG 2.1.1).

Controls that only depend on `data-table-core` **do not** install this file. Your customized `table.tsx` is safe.

- Want our version? Install `@niko-table/data-table-ui` yourself.
- Want to keep yours? That works if it exports `TableComponent`.

> **Note:** Our `table.tsx` is **100% backward compatible** with existing Shadcn tables. If you already have a `table.tsx` and install `data-table` or `data-table-ui`, the CLI asks before overwriting.

### Monorepo / Non-Standard Layouts

If your UI components live in a non-standard path (e.g., `packages/ui/src/components/` instead of `src/components/ui/`), the shadcn CLI may put `table.tsx` in the wrong place. This is a known shadcn CLI quirk with `registry:ui` paths.

**Workaround:**

1. After installing, check where `table.tsx` landed.
2. If it is in a nested `ui/` folder, move it to your real UI components path.
3. Make sure it exports `TableComponent`:

```tsx
// Your existing table.tsx — add this function and export
function TableComponent({
  className,
  ...props
}: React.ComponentProps<"table">) {
  return (
    <table
      data-slot="table"
      className={cn("w-full caption-bottom text-sm", className)}
      {...props}
    />
  )
}

// Add TableComponent to your existing exports
export {
  TableComponent,
  Table,
  TableHeader,
  // ... your other exports
}
```

## Your First Table

Build a simple table first. Add features later.

<Steps>
  1. **Start by defining your data**

     This data is a list of users with names and emails.

     ```tsx title="components/example-table.tsx"
     type User = {
       id: string
       name: string
       email: string
       status: "active" | "inactive"
     }

     const data: User[] = [
       { id: "1", name: "John Doe", email: "john@example.com", status: "active" },
       { id: "2", name: "Jane Smith", email: "jane@example.com", status: "active" },
       { id: "3", name: "Bob Johnson", email: "bob@example.com", status: "inactive" },
     ]
     ```

2. **Define your columns**

   Columns say how each field is shown.

   ```tsx title="components/example-table.tsx"
   import type { DataTableColumnDef } from "@/components/niko-table/types"

   const columns: DataTableColumnDef<User>[] = [
     {
       accessorKey: "name",
       header: "Name",
     },
     {
       accessorKey: "email",
       header: "Email",
     },
     {
       accessorKey: "status",
       header: "Status",
       cell: ({ row }) => (
         <span
           className={
             row.original.status === "active"
               ? "text-success"
               : "text-muted-foreground"
           }
         >
           {row.original.status}
         </span>
       ),
     },
   ]
   ```

3. **Build your table**

   Put the table together with DataTable components.

   ```tsx title="components/example-table.tsx"
   import { DataTableRoot } from "@/components/niko-table/core/data-table-root"
   import { DataTable } from "@/components/niko-table/core/data-table"
   import {
     DataTableHeader,
     DataTableBody,
   } from "@/components/niko-table/core/data-table-structure"

   export function ExampleTable() {
     return (
       <DataTableRoot data={data} columns={columns}>
         <DataTable>
           <DataTableHeader />
           <DataTableBody />
         </DataTable>
       </DataTableRoot>
     )
   }
   ```

</Steps>

## Optional Dependencies

Some features need extra dependencies:

### URL State Management (nuqs)

To keep table state in the URL, install [nuqs](https://nuqs.dev/):

```bash
npm install nuqs
```

nuqs keeps filters, pagination and sorting in sync with the URL.

### Sortable/Draggable Rows

For drag-and-drop row reordering, install the registry block. It brings its `@dnd-kit` dependencies:

<CliCommandCode action="run" command="shadcn@latest add @niko-table/data-table-row-dnd" />

See the [Row DnD Table example](/examples/row-dnd-table/). The sortable parts follow [DiceUI Sortable](https://www.diceui.com/docs/components/sortable) patterns.
