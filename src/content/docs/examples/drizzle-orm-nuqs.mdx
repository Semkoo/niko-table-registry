This is the [Drizzle ORM](/examples/drizzle-orm/) table with its state stored in the URL via [nuqs](https://nuqs.dev/). Use it when users should be able to share, bookmark or reload a filtered, sorted or paginated view.

- **Same backend.** The query code (`buildWhere`, `buildOrderBy`, `computeFacets`) does not change.
- **Different state source.** Local `useState` becomes `useQueryStates`.

For the details, read the [Drizzle ORM](/examples/drizzle-orm/) guide (SQL layer) and the [Server-Side Nuqs Table](/examples/server-side-nuqs-table/) (URL layer). This page only shows how they combine.

## Live demo (mocked)

- Filter or sort, then reload. The URL restores the view.

## What changes vs the Drizzle guide

Only the state layer changes. The data fetch, `buildWhere`, `buildOrderBy`, `computeFacets` and the API route stay the same.

- **State lives in the URL.** `useQueryStates` replaces the `useState` slices for page, sorting, filters, search and column visibility. It uses the same parsers as the [Server-Side Nuqs Table](/examples/server-side-nuqs-table/#url-state-parsers).
- **The query key is the URL.** TanStack Query keys off the URL state.
  - A shared link hits the same cache entry.
  - An SSR page can run the same query from the incoming search params.
- **`filterId` is stripped on write** (`serializeFiltersForUrl`) and **regenerated on read** (`normalizeFiltersFromUrl`). This keeps URLs short.
- **Filter rules split by type.** The advanced menu's AND rules live in the `filters` param. OR and MIXED rules move to the `global` param.

## Toolbar facets on a server-side table

The Category and Brand facets get their options from the server (`computeFacets`). They need server counts, not counts from the client:

```tsx showLineNumbers
<DataTableFacetedFilter
  accessorKey="category"
  title="Category"
  options={categoryFacetOptions} // server counts, count-0 dropped, selection pinned
  multiple
  dynamicCounts={false} // don't recount from the client's current page
  limitToFilteredRows={false} // don't narrow from client rows either
/>
```

The client only holds the current page, so the server must count and narrow.

- `dynamicCounts={false}` and `limitToFilteredRows={false}` turn off the client-side passes.
- The example narrows the list itself. It drops `count === 0` options but keeps any selected value so you can still remove it.

## When to Use

**✅ Use Drizzle ORM + Nuqs when:**

- You use the [Drizzle ORM](/examples/drizzle-orm/) server-side table
- Views must be shareable, bookmarkable, or survive a refresh
- You want SSR to render the first paint from the URL search params

**❌ Consider other options when:**

- A clean URL matters more than shareability: use the [Drizzle ORM](/examples/drizzle-orm/) guide as is
- You do not use Drizzle: the [Server-Side Nuqs Table](/examples/server-side-nuqs-table/) shows the same URL layer over a database-agnostic API
