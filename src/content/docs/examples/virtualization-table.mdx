Uses `@tanstack/react-virtual` to keep only the rows in the viewport in the DOM, so render cost stays flat at 100,000 rows and beyond. Use it for large datasets that are already loaded. It is a drop-in swap: replace `DataTableBody` with `DataTableVirtualizedBody` and give it a row-height estimate. Every other Niko Table add-on still works on top.

## Introduction

The Virtualization Table uses virtual scrolling to render large datasets (1000+ rows) by drawing only the visible rows. It stays smooth with 100,000+ rows. The [Niko Grid stress test](/data-grid/introduction/) pushes the same approach to 500,000.

## Prerequisites

We are going to build a table of products with virtualization. Here's what our data looks like:

```tsx showLineNumbers
type Product = {
  id: string
  name: string
  category: string
  price: number
  stock: number
  status: "in-stock" | "low-stock" | "out-of-stock"

// Generate large dataset
const largeData: Product[] = Array.from({ length: 100_000 }, (_, i) => ({
```

## Virtualized Components

### DataTableVirtualizedHeader

The virtualized version of the table header.

```tsx
<DataTableVirtualizedHeader />
```

### DataTableVirtualizedBody

The virtualized version of the table body. It renders only visible rows.

```tsx
<DataTableVirtualizedBody>
  <DataTableVirtualizedEmptyBody />
</DataTableVirtualizedBody>
```

### DataTableVirtualizedEmptyBody

The empty state for virtualized tables.

```tsx
<DataTableVirtualizedEmptyBody />
```

### DataTableVirtualizedSkeleton

The skeleton loading state for virtualized tables. It shows skeleton rows while data loads.

```tsx
<DataTableVirtualizedBody>
  <DataTableVirtualizedSkeleton rows={5} />
  <DataTableVirtualizedEmptyBody />
</DataTableVirtualizedBody>
```

### DataTableVirtualizedLoading

A simple loading spinner for virtualized tables. It shows a centered loading indicator.

```tsx
<DataTableVirtualizedBody>
  <DataTableVirtualizedLoading />
  <DataTableVirtualizedEmptyBody />
</DataTableVirtualizedBody>
```

**Note:** Use `DataTableVirtualizedSkeleton` for a detailed loading state that mimics the table. Use `DataTableVirtualizedLoading` for a simple spinner.

## Required: Fixed Height

Virtualization needs a fixed height on the `DataTable` component:

```tsx showLineNumbers
<DataTable height={600} className="rounded-lg border">
  <DataTableVirtualizedHeader />
  <DataTableVirtualizedBody>
    <DataTableVirtualizedSkeleton rows={5} />
    <DataTableVirtualizedEmptyBody />
  </DataTableVirtualizedBody>
</DataTable>
```

## Controlled State

Manage table state yourself:

```tsx showLineNumbers
import { useState } from "react"
import type {
  SortingState,
  ColumnFiltersState,
  PaginationState,
} from "@tanstack/react-table"

export function ControlledVirtualizationTable({ data }: { data: Product[] }) {
  const [sorting, setSorting] = useState<SortingState>([])
  const [columnFilters, setColumnFilters] = useState<ColumnFiltersState>([])
  const [pagination, setPagination] = useState<PaginationState>({
    pageIndex: 0,
    pageSize: 50,
  })
  const [globalFilter, setGlobalFilter] = useState("")

  return (
    <DataTableRoot
      data={data}
      columns={columns}
      config={{
        enablePagination: true,
        enableSorting: true,
        enableFilters: true,
      }}
      state={{
        sorting,
        columnFilters,
        pagination,
        globalFilter,
      }}
      onSortingChange={setSorting}
      onColumnFiltersChange={setColumnFilters}
      onPaginationChange={setPagination}
      onGlobalFilterChange={setGlobalFilter}
    >
      <DataTableToolbarSection>
        <DataTableSearchFilter placeholder="Search products..." />
        <DataTableViewMenu />
      </DataTableToolbarSection>

      <DataTable height={600} className="rounded-lg border">
        <DataTableVirtualizedHeader />
        <DataTableVirtualizedBody>
          <DataTableVirtualizedSkeleton rows={5} />
          <DataTableVirtualizedEmptyBody />
        </DataTableVirtualizedBody>
      </DataTable>

      <DataTablePagination pageSizeOptions={[50, 100, 200, 500]} />
    </DataTableRoot>
  )
}
```

## When to Use

**✅ Use Virtualization Table when:**

- You have 1000+ rows
- Performance is critical
- Users need smooth scrolling
- The dataset is too large for regular pagination

**❌ Don't use Virtualization Table when:**

- You have under 1000 rows (use [Basic Table](/examples/basic-table/))
- You need variable row heights (virtualization works best with fixed heights)
- You need complex row interactions (virtualization has limits)

## Performance Tips

1. **Set a fixed height.** Always give `DataTable` a fixed height.
2. **Use even row heights.** Virtualization works best with uniform rows.
3. **Memoize columns.** Wrap column definitions in `useMemo`.
4. **Use larger page sizes.** Page sizes of 50 to 500 work better with virtualization.
